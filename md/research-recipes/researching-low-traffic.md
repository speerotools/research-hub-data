# Researching With Low Traffic

**We can't test because traffic is too low**

> We don't have the volume to be statistically significant, so every change is a leap of faith.

How might we build evidence for decisions when traffic can't support A/B tests?

## You'll recognise this when

- Sessions too low to reach significance in a realistic test window

- High-stakes pages with thin behavioural data

- Polls and analytics too sparse to read

- Decisions resting on opinion or the loudest voice

## What this recipe does

The site doesn't get enough traffic to run reliable A/B tests or gather meaningful poll and analytics data, so decisions default to opinion. This recipe builds evidence with methods that bring their own participants instead of borrowing yours.
A UX heuristic review and a competitor review set an expert baseline and show how others in the category solve the same problems, with no traffic required. Recruited-panel methods then carry the focus work: remote usability sessions show real people from your audience attempting the core journey, and copy testing checks the message lands with the people it is written for. Preference and prototype tests stand in for the A/B test at the validation step, weighing a proposed change against the current version with a recruited sample. The result is a decision backed by several independent signals, none of which needed the traffic you don't have.

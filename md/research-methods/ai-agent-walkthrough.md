# AI Agent Walkthrough

AI agents attempt tasks on a prototype or live site, sometimes acting as personas, and report where they got stuck, what broke and what confused them. It works like an automated expert pass rather than a usability study with real people.

| | |
|---|---|
| Stage | Explore, Focus |
| Data type | Qualitative |
| Strength of signal | Low |
| Effort | Low |
| Surface area | Any surface |

## When to reach for it

Run a quick pre-flight check on a prototype before booking real participants.Catch broken flows, dead ends and obvious friction on key journeys.Add a second automated pass alongside a UX heuristic review.

## Strengths

Fast and repeatable, so it can run on every build or variant.
Catches functional breakage that people would hit before any test runs.
No recruiting or scheduling.

## Limits

Agents fail tasks real people complete easily, and push through friction that stops real people, so findings include false positives and misses.
The think-aloud commentary is generated, not observed, so it is not real user reasoning.
It can't measure satisfaction, trust or how hard a task felt.

## Practical considerations

Practical considerations

### Pair it
Follow with Remote Usability Studies with real participants before acting on anything beyond clear breakage.

### Triage findings
Treat each reported issue as a lead to verify, not a confirmed problem.

### Scope
This covers persona-style walkthroughs and QA agents for journeys. Engineering test automation suites sit outside the hub.
